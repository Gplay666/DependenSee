# Словарь данных

## Файлы набора

- `discussions.csv` — таблица, UTF-8, разделитель `,`, первая строка — заголовки.
- `discussions.json` — массив объектов; отсутствующие значения представлены как `null`.
- `sources.md` — описание площадок, доступа и ограничений.
- `collection_log.md` — журнал сбора и решений.

Одна строка — одна публикация (пост, тема или issue), не отдельный комментарий и не ответ. Для GitHub issue считается отдельной публикацией. В наборе 134 записи.

## Поля

| Поле | Тип | Описание |
|---|---|---|
| `id` | string | Внутренний идентификатор `DS-001`…; присваивается после сортировки по дате (сначала новые), затем по источнику и URL. |
| `source` | string | Площадка и, где применимо, сообщество/репозиторий: `Reddit (r/linuxquestions)`, `Ask Ubuntu`, `Unix & Linux Stack Exchange`, `Fedora Discussion`, `GitHub (org/repo)`, `Arch Linux Forums`. |
| `url` | string | Прямая ссылка на публикацию. Проверена на момент сбора. |
| `title` | string | Заголовок в том виде, в каком он опубликован на площадке. |
| `date` | string | Дата публикации, `YYYY-MM-DD` (UTC для Reddit и Stack Exchange). |
| `distro` | string \| null | Дистрибутив, к которому относится публикация. Правила вывода — ниже. |
| `problem_category` | string | Одна основная категория из контролируемого словаря. |
| `problem_description` | string | Краткое описание проблемы на английском, по содержанию публикации. |
| `user_request` | string | Что автор явно просит или хочет получить. Не вывод исследователя о «потребности рынка». |
| `mentions_visualization` | boolean | Прямое упоминание визуализации зависимостей: граф, дерево, карта, диаграмма, интерактивное представление. Косвенное упоминание «списка» или «показать размер» сюда не относится. |
| `mentions_dependencies` | boolean | В тексте обсуждаются зависимости, обратные зависимости, дерево/граф зависимостей или orphan-пакеты. |
| `mentions_cleanup` | boolean | Обсуждаются удаление, очистка, autoremove, purge, поиск мусора или брошенных пакетов. |
| `mentions_disk_space` | boolean | Явно упоминаются место на диске, размер пакетов, переполнение раздела или освобождение места. |
| `mentions_safety` | boolean | Выражены страх, риск, неуверенность или уже произошла поломка при удалении/обновлении. |
| `score` | integer \| null | Голоса/рейтинг публикации. Для Reddit — снимок Arctic Shift; для Stack Exchange — рейтинг вопроса; для GitHub, Fedora и Arch — `null` (см. ниже). |
| `comments_count` | integer \| null | Число комментариев/ответов/реплаев. Точная семантика зависит от площадки (см. ниже). |
| `evidence` | string | Короткая дословная цитата из тела или заголовка публикации. Цитата проверена как подстрока после нормализации. |

## Категории

- `unused_packages` — пакеты, которые установлены, но не используются или больше не нужны пользователю.
- `orphaned_packages` — пакеты без обратных зависимостей; сюда же отнесены споры о разных определениях orphan и ошибки инструментов orphan-детекции.
- `dependency_opacity` — непонятно, почему пакет установлен, что от него зависит или почему autoremove/remove ведёт себя неожиданно.
- `visualization_request` — прямой запрос на дерево, граф, карту или интерактивное представление зависимостей.
- `removal_safety` — страх сломать систему, неудачное удаление, предложение удалить критичные пакеты, необходимость проверить список перед подтверждением.
- `cleanup_disk_space` — очистка ради места на диске, размеры пакетов, переполненные разделы, старые ядра и кэши.
- `package_tool_usability` — неудобство существующих менеджеров пакетов и чистильщиков: нет autoremove, нет предпросмотра, ложные срабатывания, неполное удаление, отсутствие инструмента.
- `package_inventory` — нужен учёт установленного: список вручную установленных пакетов, история установок, отделение приложений от зависимостей.
- `remote_server_analysis` — анализ пакетов/диска на сервере или удалённой машине, в том числе без установки инструментов на неё.

Категория отражает главную проблему публикации. Флаги при этом могут указывать на дополнительные аспекты.

## Правила для `distro`

1. Если дистрибутив явно назван в заголовке или теле — используется он.
2. Для тематических сабреддитов (`r/Ubuntu`, `r/debian`, `r/archlinux`, `r/fedora`, `r/linuxmint`) допускается контекст сабреддита, если в тексте нет другого дистрибутива.
3. Для GitHub — целевой дистрибутив проекта, если сама issue не называет другой: `dnf5` → Fedora, `paru`/`yay` → Arch Linux, `mintupdate` → Linux Mint, `synaptic`/`unattended-upgrades` → Ubuntu.
4. Если публикация кросс-дистрибутивная либо дистрибутив не указан — `null`. `null` не означает «неизвестно, что это Linux»; это отсутствие однозначного указания.

Значения в наборе: Ubuntu, Debian, Fedora, Arch Linux, Linux Mint, Manjaro, CachyOS, Pop!_OS, Lubuntu, Kubuntu, Xubuntu, Ubuntu Studio, Raspbian, CentOS; `null` — 21 строка.

## Метрики вовлечённости

| Площадка | `score` | `comments_count` | Особенность |
|---|---|---|---|
| Reddit | Рейтинг поста в архиве Arctic Shift | `num_comments` из того же снимка | Не live-значения; могут отличаться от текущих на reddit.com. |
| Ask Ubuntu / Unix & Linux | Рейтинг вопроса из Stack Exchange API | `answer_count` | Это число ответов, а не комментариев; комментарии API отдельно не собирались. |
| Fedora Discussion | `null` | `posts_count - 1` | Replies в Discourse; лайки не используются как голоса. |
| GitHub | `null` | Число комментариев issue | Реакции (`reactions`) не приравниваются к голосам, поэтому score оставлен пустым. |
| Arch Linux Forums | `null` | `replies` из поисковой выдачи | Отдельного рейтинга у постов нет. |

## Evidence

- Для Reddit, Stack Exchange, Fedora, GitHub и Arch цитата берётся из сохранённого тела или заголовка первой публикации.
- Если тело пустое (например, пост-картинка), используется дословный заголовок; это отмечено в журнале.
- При проверке нормализуются HTML-сущности, типографские кавычки/тире, пробелы и регистр. Смысл и порядок слов не меняются.
- `build_dataset.py` останавливает сборку, если хотя бы одна цитата не найдена в заголовке или теле.

## Пропуски и null

- `null` используется, когда данных нет или они не применимы, а не как «0».
- В CSV `null` представлен пустой ячейкой; булевы значения — строками `true`/`false`.
- Для 46 строк `score` пуст: это GitHub (20), Fedora (20) и Arch Linux Forums (6) — у этих площадок нет сопоставимого рейтинга.

## Отбор и исключения

- Только публично доступные страницы; CAPTCHA и анти-бот-защита не обходились.
- Удалённые/закрытые для просмотра публикации исключены.
- Саморекламные посты разработчиков не включались в основную выборку: Reddit `1ujnn4j` (анонс инструмента) и `1r4t6jc` (анонс собственного TUI). Это решение зафиксировано в журнале.
- Анонсы сопровождения пакетов (maintainer orphan announcements) не путались с пользовательской очисткой и не включались.
- Дубликаты по URL отсутствуют; одинаковые заголовки на разных площадках считаются разными публикациями.
- Приоритет отдан пользовательским обсуждениям, а не рекламным и обзорным материалам.
